# 分阶段开发与验收计划

## 执行规则

每阶段只在前一阶段通过后开始。阶段完成顺序固定为：代码实现、自动化测试、人工验收、安全检查、Git 提交与推送。真实萤石能力与模拟数据必须显式区分。

## 阶段一：项目骨架

范围：

- Vue 3 + TypeScript 前端；
- FastAPI + SQLAlchemy 后端；
- 用户登录、刷新、登出和当前用户；
- 存活与基础设施就绪检查；
- MySQL、Redis、MinIO 与 Docker Compose；
- 后端和前端单元测试；
- 第一阶段运行、测试和故障排查文档。

不在本阶段：萤石 Token、设备同步、套餐激活、真实播放器、AI 推理、风险结果和告警。

退出条件：

- `docker compose up --build -d` 后基础服务健康；
- `/health` 返回 200，`/ready` 能反映各依赖真实状态；
- 管理员可登录、刷新令牌、访问 `/me` 并登出；
- 无效密码、停用用户、无效/重复使用刷新令牌均被拒绝；
- 前后端单元测试、类型检查和构建通过；
- `.env` 和密钥未进入 Git。

- [x] Redis 缓存 Token，提前刷新并加锁；

- [ ] 使用官方测试账号完成集成测试。

配置、运行和人工验收步骤见 [phase2-ezviz-guide.md](./phase2-ezviz-guide.md)，自动化清单见 [testing-phase2.md](./testing-phase2.md)。

## 阶段二 A：离线视频模拟与数据集管理

当前状态：代码实现完成，等待用户使用有效视频文件进行人工验收。该阶段用于解决暂时没有萤石摄像机时的研发阻塞，不替代第二阶段真实设备验收。

- [x] 扫描 `data/offline-videos`，不复制、不移动、不删除用户视频；
- [x] 登记数据集、动作标签、来源地址和许可说明；
- [x] 自动识别常见 `Fall`、`ADL`、`NearFall` 目录标签，并允许人工校正；
- [x] 使用短时签名地址回放本地视频，不暴露服务器绝对路径；
- [x] 前端明确显示“离线来源”和“AI 推理未启用”；
- [x] 视频文件与 `.env` 均不进入 Git；
- [x] 后端、前端单元测试与类型检查；
- [ ] 使用至少一段有效跌倒视频和一段日常活动视频完成人工验收。

运行步骤见 [phase2a-offline-video-guide.md](./phase2a-offline-video-guide.md)，测试清单见 [testing-phase2a.md](./testing-phase2a.md)。人工验收通过后，再进入本地 AI 姿态与时序基线；套餐激活和萤石 Web 播放保留为取得硬件后的真实集成门禁。

- [x] 服务端五个套餐槽位映射；
- [x] 赛事权益摘要、Token 非明文状态、代金券人工确认状态与激活阻塞项；
- [x] 管理员二次确认；
- [x] `slot + serial + channel` 幂等保护；
- [x] 官方结果解析、脱敏响应和审计记录；
- [x] 覆盖成功、Token 失效、参数错误、重复和越权场景；

使用步骤见 [phase3-package-activation-guide.md](./phase3-package-activation-guide.md)，测试清单见 [testing-phase3.md](./testing-phase3.md)。

## 当前优先支线：独立多模态算法训练

当前开发方向调整为先完成平台无关的多模态跌倒风险预测算法。服务器只用于数据处理、训练、评测和模型导出，不部署 Web、FastAPI、数据库或萤石服务。阶段四 Web 播放和原阶段五平台 AI 取流暂缓，待算法形成固定输入输出和正式模型包后再继续。

- [ ] A0：多模态输入输出协议、数据 manifest、受试者划分和泄漏检查；
- [ ] A1：SAFER + PoseC3D 视觉工程基线；
- [ ] A2：SAFER + SkateFormer 行为与短期风险基线；
- [ ] A3：UP-Fall + TCN 的 IMU 单模态基线；
- [ ] A4：使用同步视频、IMU、环境和 EEG 数据训练多模态基线；
- [ ] A5：质量门控、缺失模态适应和 QAF 消融；
- [ ] A6：跨受试者、跨视角、外部数据和故障鲁棒性评测；
- [ ] A7：导出 ONNX/PyTorch 模型包、输入输出 Schema、阈值、指标和模型卡。

算法结构和评价体系见 [qaf-skateformer-algorithm-design.md](./qaf-skateformer-algorithm-design.md)，完整训练执行步骤见 [ai-training-and-inference-execution-plan.md](./ai-training-and-inference-execution-plan.md)。A0～A7 完成前不修改 FastAPI 和 Vue 来适配未冻结的模型接口。

## 阶段四：Web 视频播放

- 后端鉴权获取最小播放参数；
- 集成萤石官方播放器；
- 页面离开后停止并销毁播放器；
- 至少一路真实设备视频播放；
- 家属只能查看绑定老人。

## 阶段五：AI 取流与姿态基线

- 算法、官方代码、预训练权重和适用边界见 [algorithm-and-model-research.md](./algorithm-and-model-research.md)；
- 建立 `AlgorithmRegistry`、`ModelRegistry` 与可替换 `ModelRunner`，禁止把第三方模型直接写死在业务模块中；
- 输入源适配器同时支持离线文件和萤石云流；
- 独立 AI 播放地址；
- FFmpeg 解码、10 FPS 初始采样和有界帧队列；
- Pose 与跟踪适配器；
- WebSocket 推送骨架、质量和性能；
- 断流恢复及 30 分钟稳定性测试。

## 阶段六：风险预测与跌倒状态机

- 姿态和运动特征；
- 个体基线、短期失稳和事件状态机；
- 模型/规则/阈值版本化；
- 事件级评测、误报分析和场景报告。

## 阶段七：事件录像

- 编码包或分段文件环形缓冲；
- 事件前 15 秒、后 30 秒；
- MinIO 媒体与事件关联；
- 保留期限、清理任务和下载审计。

## 阶段八：分级告警与统计

- WebSocket 站内告警；
- 告警确认、处置、误报和恢复；
- 角色与老人绑定范围过滤；
- 风险日/周/月趋势和数据一致性测试。

## 阶段九：并发、终验与参赛材料

- 逐步扩展至五路设备；
- 单路故障隔离、动态降帧和资源监控；
- 24 小时稳定性与恢复测试；
- 模型卡、数据说明、测试报告、部署包和演示脚本；
- 代码、实测结果、视频演示和申报材料一致性审计。
