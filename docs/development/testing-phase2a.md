# 第二阶段 A 测试与验收清单

## 自动化测试范围

后端覆盖：

- 只扫描支持的视频扩展名；
- 根据目录名推断跌倒与日常活动标签；
- 不向接口返回服务器绝对路径；
- 未登录返回 401，非管理员返回 403；
- 元数据修订不修改原始视频文件；
- 短时签名播放票据和媒体响应；
- 非浏览器原生格式自动转换为 MP4，并复用已生成缓存；
- 转换后的媒体响应使用 `video/mp4`，不沿用原 AVI/MKV/MOV 类型；
- 无效票据被拒绝；
- 文件移除后重新扫描会标记缺失；
- Ruff 代码规范检查。

前端覆盖：

- 加载视频清单和库状态；
- 扫描后重新加载清单；
- 修订元数据并更新状态；
- 请求短时播放票据；
- TypeScript 类型检查和生产构建。

## 运行自动化测试

在项目根目录执行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& .\scripts\test-phase2a.ps1
```

该脚本会执行当前仓库的全部后端和前端测试，因此同时覆盖第一、第二和第二阶段 A 的回归检查。脚本为 pytest 使用项目 `tmp` 下的独立临时目录，避免 Windows 全局临时目录权限异常影响测试。

## 人工验收素材

至少准备两段可正常播放的视频：

- 一段模拟跌倒；
- 一段走路、坐下、睡觉或捡物等日常活动。

素材必须来自正式公开数据集，或已经取得参与者明确授权的自行采集视频。不要把测试素材提交 Git。

## 人工验收步骤

1. 将两段视频分别放入 `data/offline-videos/Test/Fall` 和 `data/offline-videos/Test/ADL`；
2. 启动前后端并使用管理员账号登录；
3. 打开“离线视频”，点击“扫描视频目录”；
4. 确认新增数量、可用视频数量和数据集数量正确；
5. 确认两段视频分别推断为“跌倒”和“日常活动”；
6. 编辑其中一段，填写正式来源地址和许可说明，刷新页面确认仍然存在；
7. 对两段视频分别点击“模拟运行”，确认能够播放、拖动进度条和切换倍速；AVI/MKV/MOV 首次播放应等待兼容 MP4 生成，第二次应直接复用缓存；
8. 确认播放器外框随实际视频宽高比变化，例如 320×240 素材显示为 4:3，而不是固定拉伸；
9. 确认页面显示“离线来源”和“AI 推理未启用”；
10. 临时移动一段视频，重新扫描，确认记录显示“已缺失”且无法生成播放地址；
11. 将视频放回原路径并再次扫描，确认记录恢复“可用”；
12. 使用护理人员账号确认不能访问该页面和接口；
13. 执行 `git status --short`，确认视频文件和 `data/local/offline-video-cache` 缓存没有出现在待提交列表中。

## 阶段通过标准

- 自动化测试、Ruff、TypeScript 检查和构建全部通过；
- 至少一段跌倒和一段 ADL 视频完成真实浏览器回放；
- 目录扫描不会移动或删除原始素材；
- 页面和 API 不暴露服务器绝对路径；
- 数据来源、许可和动作标签可追溯；
- 所有离线能力均未被描述为萤石实测或 AI 识别结果。

人工验收通过后再执行 Git 提交与推送。
